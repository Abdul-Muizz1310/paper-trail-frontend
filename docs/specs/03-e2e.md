# Spec 03 — End-to-end

## Scope

Playwright suite that drives a real browser against the live Next.js dev server, with the backend either (a) mocked via Playwright's `route.fulfill` or (b) pointed at the real deployed backend for the smoke scenario.

Location: `tests/e2e/debate-flow.spec.ts`. Config: `playwright.config.ts` with `baseURL` from `NEXT_PUBLIC_SITE_URL` (defaulting to `http://localhost:3000`).

## Two modes

1. **Mocked mode (default, runs in CI)** — the browser calls the frontend's own signing proxy ([spec 05](05-backend-proxy.md)), so the UI specs intercept `**/api/backend/**` in the browser and fulfil it from fixtures under `tests/e2e/fixtures/`. The proxy's upstream fetch runs in the Next server, where `page.route` cannot reach, so the dev server is pointed at a local mock backend (`tests/e2e/global-setup.ts`) with a throwaway key; `tests/e2e/proxy.spec.ts` drives that path with no browser mocks. Deterministic. Fast.
2. **Live mode (`E2E_LIVE=1`, nightly only)** — the proxy forwards to `https://paper-trail-backend-jjpf.onrender.com`, signing with the `PAPER_TRAIL_FRONTEND_SIGNING_KEY_PRIVATE` repository secret. Flaky by nature (Render cold starts, LLM variability); not gated on PR merge.

## Core scenario

> User enters a claim → watches the debate arena populate over SSE → sees the verdict → clicks through to the transcript and reads the markdown.

### Fixture setup (mocked mode)

- `POST /debates` → 201 `{ debate_id: "11111111-1111-1111-1111-111111111111", stream_url: "/debates/11111111.../stream" }`
- `GET /debates/{id}/stream` → served by a small handler that pushes a scripted sequence of SSE events over time (state × 3, then done).
- `GET /debates/{id}` → returns three different bodies depending on which call number (first call: 1 round; second: 2 rounds; third: complete with verdict).
- `GET /debates/{id}/transcript.md` → returns a fixture markdown file.

### Implemented cases (`tests/e2e/debate-flow.spec.ts`, gated in CI)

#### Pass

- **P1 — Happy path (mocked)**
  1. Visit `/`.
  2. Fill the claim textbox with "Remote work reduces productivity.".
  3. Click submit.
  4. Assert URL is `/debates/1111...`.
  5. Wait for `<JudgeVerdict>` with `data-variant="true"` to appear within 10s.
  6. Click the "transcript" link.
  7. Assert URL ends with `/transcript` and the transcript contains a fixture-specific heading ("Final reasoning").

- **P2 — Stream cut is renewed (mocked)**
  1. The first `GET /debates/{id}/stream` sends a `running` state, then `{ type: "done", reason: "timeout" }` (the backend's 120 s per-connection cap).
  2. The second stream sends the `done` state with verdict `TRUE`.
  3. Visit `/debates/1111...`; assert `<JudgeVerdict data-variant="true">` appears and the stream was opened exactly twice ([spec 01](01-sse.md) P7).

#### Failure

- **F1 — Invalid UUID route**
  1. Visit `/debates/not-a-uuid`.
  2. Assert the Next.js 404 page renders; assert no SSE connection is opened (verify via `page.on('request')` filter — zero requests to `**/stream`).

- **F2 — Backend 404 on debate**
  1. Mock `GET /debates/{id}` → 404.
  2. Visit `/debates/1111...`.
  3. Assert the error state renders with a "Go home" link wired to `/`.

- **F3 — Transcript backend error → inline error state**
  1. Mock `GET /debates/{id}` → 404.
  2. Visit `/debates/1111.../transcript`.
  3. Assert the inline `transcript-error` state renders (the transcript route is client-rendered — a valid-UUID backend 404 surfaces an inline error, not a Next.js 404 page; invalid UUIDs still `notFound()`).

- **F4 — Submit failure restores input**
  1. Mock `POST /debates` → 500.
  2. Visit `/`, type "my precious claim", submit.
  3. Assert an inline error with role `alert` appears.
  4. Assert the input still contains "my precious claim" (no data loss).

- **F5 — Debate ends in error**
  1. Mock `GET /debates/{id}` and the stream with `status: "error"` and no verdict.
  2. Visit `/debates/1111...`.
  3. Assert the `debate-failed` alert renders, with no `<JudgeVerdict>` and no transcript link ([spec 00](00-pages.md) F8).

## Live smoke (nightly, `E2E_LIVE=1`)

Implemented as `L1 live smoke (nightly only, real backend)` in `tests/e2e/debate-flow.spec.ts`, gated by
`test.skip(!process.env.E2E_LIVE, ...)` so no PR-gating run depends on the live backend. Scheduled nightly
(and runnable by hand with `gh workflow run nightly-e2e.yml`) by `.github/workflows/nightly-e2e.yml`.
The job **fails when the scenario fails** (no `continue-on-error`), and uploads the trace and screenshots.

- **L1** drives the app as a visitor does, through the signing proxy, with the real key:
  1. `GET /api/backend/health` answers 200 with `status: "ok"`, `db: "ok"` within 150 s (wakes the
     free-tier backend from a cold start; a 503 means the proxy has no key, a 401 that the backend
     rejected its token).
  2. Submit "The Eiffel Tower is in Paris." with max-rounds 3 (the fewest the UI offers).
  3. The URL becomes `/debates/<uuid>` within 60 s: the create call went through the proxy.
  4. Within 330 s (the backend's run deadline is 300 s) either `<JudgeVerdict>` or the `debate-failed`
     alert renders; the test fails at once, with that message, if it is the failure.
  5. The verdict is `data-variant="true"` with confidence ≥ 0.5.
  6. The transcript link opens `/debates/<uuid>/transcript`, which renders the backend's `## Verdict`
     heading.
- **Budget.** One run is one real debate, about four requests of the account's 50 free-model requests a
  day, so live mode never retries (`playwright.config.ts`).
- **Why it used to fail.** Until 2026-10-16 the browser called the backend directly, without a token; with
  `DEMO_MODE=false` every `POST /debates` answered 401, the page never left home, and the test could only
  report "`judge-verdict` not found" after 90 s (`continue-on-error` hid it). The selector was right: the
  proxy of [spec 05](05-backend-proxy.md) fixed the cause. Two app bugs that produce the same symptom are
  fixed alongside: a stream cut at the backend's 120 s cap froze the page without a verdict (P2), and a
  failed debate rendered nothing (F5).
